# Отчёт по этапу 1. Настройка окружения и основы Android/Kotlin

Проект: «Календарь задач», пакет `ru.university.taskcalendar`, язык Kotlin, шаблон «Empty Views Activity».

## 1. Структура проекта

| Файл / папка | Назначение |
|---|---|
| `app/src/main/java/.../` | Код приложения на Kotlin (Activity, адаптер, ViewModel, база данных) |
| `app/src/main/res/layout/` | XML-разметка экранов |
| `app/src/main/res/values/strings.xml` | Все тексты интерфейса. Вынесены в ресурсы, чтобы не дублировать их в разметке и коде и чтобы приложение можно было перевести на другой язык |
| `app/src/main/res/values/themes.xml`, `values-night/themes.xml` | Тема оформления (`Theme.Material3.DayNight.NoActionBar`) для светлого и тёмного режима |
| `AndroidManifest.xml` | Описание приложения: название, иконка, тема, список экранов (Activity) и разрешения |
| `app/build.gradle.kts` | Настройки сборки модуля: `namespace`/`applicationId` = `ru.university.taskcalendar`, `minSdk = 26` (Android 8.0), `targetSdk = 37`, `compileSdk = 37`, список зависимостей |
| `gradle/libs.versions.toml` | Каталог версий: все версии библиотек в одном месте |
| `settings.gradle.kts`, `build.gradle.kts` | Подключение модуля `:app`, репозитории библиотек, плагины |

Эмулятор (AVD) — виртуальное устройство на компьютере: на нём удобно проверять разные версии Android и размеры экранов. Физическое устройство нужно для проверки реальной производительности, датчиков и уведомлений.

## 2. XML-атрибуты, использованные в проекте

| Атрибут | Что делает |
|---|---|
| `layout_width`, `layout_height` | Размер элемента. `match_parent` — занять всё доступное место родителя; `wrap_content` — ровно по размеру содержимого; `0dp` внутри ConstraintLayout — растянуться между ограничениями |
| `id` (`@+id/...`) | Уникальное имя элемента; по нему элемент находят в коде (`findViewById`) |
| `text`, `hint` | Текст элемента / серая подсказка в пустом поле ввода (значения берутся из `@string/...`) |
| `textSize`, `textStyle` | Размер шрифта (в `sp`) и начертание (`bold`) |
| `orientation` | Направление раскладки в LinearLayout (`vertical` — сверху вниз) |
| `padding` | Внутренний отступ: от границы элемента до его содержимого |
| `layout_margin*` (`Top`, `Bottom`, `Start`, `End`) | Внешний отступ: расстояние до соседних элементов |
| `inputType` | Тип клавиатуры и допустимый ввод: `text`, `textMultiLine`, `time` |
| `minLines`, `gravity` | Минимальная высота многострочного поля; выравнивание текста внутри поля (`top`) |
| `contentDescription` | Описание для экранных дикторов (доступность), например для кнопки «+» |
| `src` | Картинка (иконка) в FloatingActionButton |
| `clipToPadding="false"` + `paddingBottom` | У списка: нижний отступ, чтобы последняя карточка не пряталась под кнопкой «+» при прокрутке |
| `layout_constraintStart_toStartOf`, `..End_toEndOf`, `..Top_toTopOf`, `..Top_toBottomOf`, `..Bottom_toBottomOf` | Ограничения ConstraintLayout: к какому краю родителя или соседнего элемента «привязан» данный элемент |
| `cardCornerRadius`, `cardElevation` | Радиус скругления и высота тени карточки CardView |
| `windowSoftInputMode="adjustResize"` (в манифесте) | При появлении клавиатуры окно сжимается, и поля ввода не перекрываются |

**ConstraintLayout** задаёт положение элементов через ограничения относительно родителя или друг друга, а не через вложенность контейнеров. Поэтому разметка получается плоской и быстрее отрисовывается.

## 3. Жизненный цикл Activity

| Метод | Когда вызывается | Что делается в проекте |
|---|---|---|
| `onCreate()` | Экран создаётся (в том числе заново после поворота) | Подключается разметка (`setContentView`), находятся элементы, ставятся обработчики нажатий, оформляется подписка на данные (`observe`) |
| `onStart()` | Экран становится видимым | Своей логики нет; именно в этот момент LiveData начинает доставлять данные подписчику |
| `onResume()` | Экран на переднем плане, с ним можно взаимодействовать | На этапе 3 здесь перезагружался список после возврата с другого экрана; на этапе 4 это не нужно, список обновляется автоматически |
| `onPause()` | Экран частично закрыт или теряет фокус (например, открылся другой экран) | Не переопределяется |
| `onStop()` | Экран полностью невидим | Не переопределяется |
| `onDestroy()` | Экран закрывается (`finish()`) или пересоздаётся системой | Не переопределяется; ViewModel при повороте сохраняется, при закрытии экрана уничтожается |

Дополнительно используется `onSaveInstanceState()` в `AddTaskActivity`: он сохраняет флаг «форма уже заполнена», чтобы после поворота не затереть введённые пользователем данные.

## 4. Kotlin: `val`/`var` и null safety (примеры из проекта)

- `val` — неизменяемая ссылка, `var` — изменяемая. По умолчанию используется `val` (`val title = titleEditText.text...`): так меньше случайных изменений и проще читать код. `var` нужен там, где значение действительно меняется (`private var currentTask: Task?`).
- `Task?` — тип, допускающий `null`; `Task` — не допускающий. Задача, найденная по id, может отсутствовать, поэтому `selectedTask` имеет тип `LiveData<Task?>`.
- `?.` (безопасный вызов): `currentTask?.let { ... }` выполнит блок, только если задача не `null`.
- `?:` (elvis): `savedInstanceState?.getBoolean(...) ?: false` — если слева `null`, будет взято `false`.
